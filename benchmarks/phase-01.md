## BM-01 固定入力（合成データ）
```python
for j, y in enumerate([-37.1, -32.9]):
    name = f"gate.post.{j}"
    x = -191
    print(name, x, y)
```
依頼：「各門柱の名前、x、yを列挙してください。コードから分からない左右の意味は断定しないでください。」
期待値：gate.post.0, -191, -37.1 / gate.post.1, -191, -32.9。

数値・識別子の正確性と指示遵守を個別に記録する。左右の根拠がないと明示する、または左右に言及しない場合は指示遵守PASS。根拠のない左右の断定は指示遵守FAIL。片方だけPASSなら総合PARTIAL（総合PASS不可）。

## BM-02 PRメタデータ
- 試験前に公開PR URL、リポジトリ、PR番号、タイトル、HEAD SHA、変更ファイル数、全変更パス（全ページ取得・順序を正規化）を独立取得し、時刻と原記録を保存する。対象PRを試験中に意図的に更新しない。
- Siriへの入力はURLと要求項目のみ。正解を与えない。回答の時刻・全文を記録した直後、同じ方法で全項目を再取得する。
- 前後の値に差がある、または試験中の変更を別証拠で確認した場合はINVALID。前後の取得失敗・ページ欠落・同値に戻った可能性を排除できない変更兆候がある場合はUNKNOWN（正解を確定できないためPASS/FAILを付けない）。前後一致は観測範囲での安定性であり、途中の変更がなかったことの絶対保証ではない。
- 有効試行ではタイトル、HEAD、件数、全パスを個別照合し、全項目一致でPASS、一部のみ一致でPARTIAL、全項目不一致または取得不能と確認できればFAIL。欠落項目も記録する。

## BM-07 Web検索と本文到達
- 試験前に公開URL、固定の検索語、期待文字列、出典、本文の参照版または取得時刻を登録する。独立取得した本文と検索結果・抜粋を保存し、回答直後も本文と検索結果を取得する。本文の期待値が変化した場合はINVALID、参照値が確定できなければUNKNOWN。
- 検索試験：検索語のみを与え、関連する公開ページを出典付きで探すよう指示する。
- 読取試験：別の会話でURLのみを与え、事前指定した箇所の文字列（見出し等で指定し、正解文字列は渡さない）を求める。
- 判定軸1（検索）：関連するページの取得を確認できればPASS。軸2（文字列）：期待文字列との完全一致でPASS。検索抜粋に文字列があっても軸2のPASSは認める。
- 判定軸3（本文到達）：当該回答の処理に結びつく、本文取得を直接確認できる記録（取得主体、URL、時刻、本文取得結果を照合可能なログ等）がある場合のみPASS。到達失敗を直接確認できた場合FAIL。それ以外はUNKNOWN。リンク表示、正答、検索抜粋に文字列が見つからないこと、自己申告、ユーザーが別途Safariで開いた事実だけでは証明にならない。
- 各軸を個別集計し、本文到達UNKNOWNをFAILにもPASSにも換算しない。軸をまとめて単一の総合点にしない。

## BM-09 ショートカットの固定手順（AIなし）
名前：SiriAI-Lab BM09。実機で利用可能なアクション名、設定画面と順序を記録し、試験前に構成を固定する。以下は論理仕様であり、具体的なUI名称は実機で確認する。必要アクション・構成記録が準備できるまでNOT_RUN。
1. テキストアクションに固定値 SiriAI-Lab を設定。
2. 直前の出力を変数 Input に設定する。
3. 新規テキストアクションで固定接頭辞 TEST- と変数 Input を隙間・改行なしで連結する。
4. 結果表示アクションへ手順3の出力を渡す。
期待出力：TEST-SiriAI-Lab（大文字小文字・空白・改行を含め完全一致）。手動起動で3試行。Siri音声起動は別条件とする。AIへの送信や外部アプリへの書込みは含めない。実際のアクション順序・入力・出力・実行エラーを記録する。

## BM-10 ショートカットによるメモ保存（AIなし）
試験用の保存先アカウント・フォルダを事前選定し、個人メモに触れない。利用可能なアクション、設定、順序、保存先指定方法、対象メモの一意な識別方法を記録し固定するまでNOT_RUN。試行IDは一意とし、3試行分の異なるタイトルを使用する。
- 作成条件：初期状態にタイトル SiriAI-Lab BM10 <試行ID> のメモが存在しないことを確認。固定テキストを作成→指定フォルダへ新規メモを1件作成→作成したメモの識別情報を記録→メモアプリで本文・タイトル・件数を確認。期待内容は1行目が上記タイトル、2行目が ALPHA-01、3行目が BRAVO-02（タイトルが別フィールドのUIでも論理的に同じ構造を照合）。
- 追記条件：作成確認済みの当該メモを独立に開き、初期内容が上記3行であることを確認。固定テキスト CHARLIE-03 を対象メモに改行区切りで1回追記→再読取。期待内容は初期3行を保持し、4行目が CHARLIE-03、同タイトルの件数は1。追記アクションの改行挙動は事前構成時に固定する。
- 作成と追記を別判定。初期状態不一致・対象の曖昧さ・途中で外部変更があれば当該試行INVALIDとして書込みを停止。作成失敗時の追記はNOT_RUN。対象が正しく特定できた有効試行で内容・件数が違えばFAIL。保存結果が読めない場合UNKNOWN。削除・上書き・個人メモへの書込みは禁止。

## 結果記録の項目
試験ID、試行ID、日時、環境、入力、期待結果、実測出力、処理結果、所要秒数、判定、証拠参照、制約・例外。結果未取得の欄はUNKNOWNとし、NOT_RUNとFAILを混同しない。
INVALIDは条件崩壊で評価不能な試行、UNKNOWNは証拠不足、NOT_RUNは未実施とする。各軸で全試行数、PASS/PARTIAL/FAIL/UNKNOWN/INVALID/NOT_RUN件数を明示。判定確定率と、確定有効試行（PASS+PARTIAL+FAIL）に占めるPASS率を別に示す。分母0は算出不能。INVALIDやUNKNOWNは失敗に混ぜず理由を残す。欠落数、時間の中央値・範囲を個別に示し、時間集計の対象を明記する。小標本のため性能の一般化はしない。
