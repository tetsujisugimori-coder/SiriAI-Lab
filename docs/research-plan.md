# SiriAI-Lab 研究計画（初版）
2026-11-28 JST / 提案版

## 目的
Siriの回答性能だけでなく、音声入力、Apple純正アプリとの統合、ショートカットによる処理の組み立て、外部AI連携を個別に評価し、実用的な活用方法を整理する。

## 研究軸
- 回答：正確性、指示遵守、複数条件、応答時間、再現性。
- 音声：日本語認識、専門用語の読み上げ、入力と出力の区別。
- 実行：メモの作成・追記、保存内容の完全性、実行確認、失敗時の挙動。
- 情報取得：公開Web検索、指定URLの読取、直接与えた資料の読解の区別。
- AI連携：画面の表示・設定・履歴等による処理経路の識別。回答の文体だけではモデルを断定しない。
- ショートカット：入力、変数、条件分岐、繰り返し、出力、アプリ連携、自動化。実機で利用できるアクションを確認してから比較する。
- 他社比較：同じ課題・入力条件でChatGPT、Gemini、Copilot等を比較。回答と端末実行能力を別軸で扱う。

## 段階
1. 既存観測の整理と基本機能の再現試験。
2. ショートカットの基礎操作と処理結果確認。
3. AI連携・ワークフロー・失敗対照。
4. 他社比較と実用ガイド。
5. 結果の可視化・公開可能な実用例の整理。

## 判定
PASS: 定義済みの条件を満たした。PARTIAL: 一部達成。FAIL: 条件を満たさないことを確認。UNKNOWN: 証拠不足。INVALID: 参照先の変動・初期状態不一致など試験条件が崩れ、評価対象にできない。NOT_RUN: 未実施。
探索観測と統制済み再現試験は区別する。単回成功を一般性能と見なさない。試験ごとの根拠・試行数・失敗を残し、未実施を成功扱いしない。UNKNOWN・INVALID・NOT_RUNは別集計し、確定有効試行のPASS率と判定確定率を併記する。取得内容と取得経路、数値の正確性と指示遵守など、異なる評価軸を混同しない。

## 記録・保全
端末・OS・言語・地域・利用画面・設定・アカウント種別（個人識別情報なし）・ネットワーク・日時・入力方式・正確な入力と出力・処理先・所要時間を可能な範囲で記録する。不明値はUNKNOWN。
公開リポジトリには匿名化された要約と合成試験データのみを原則収録。個人のメモ、認証情報、原スクリーンショット等は公開せず、必要な証拠は別途所有者限定で保全する。保全の完了は実際に照合してから記録する。
外部サービスへの送信や実データ変更を伴う試験は事前に対象を確認し、合成データ・試験用メモで行う。
変更はfeature branchとPRで管理し、mainへ直接変更しない。
